# Wallet

Личный учёт расходов в Telegram Mini App. React + TypeScript, NestJS, PostgreSQL.

Реализованы быстрый ввод расхода встроенными цифрами, история, отчёты, общий месячный бюджет, счета, категории, доходы, переводы, корректировки, возвраты, редактирование, мягкое удаление и CSV. Полный продуктовый план: [PROJECT_PLAN.md](PROJECT_PLAN.md).

## Локальный запуск в браузере

Нужны Node.js 22.12+ и PostgreSQL. Базу запустите отдельно и укажите её адрес в `DATABASE_URL`.

1. Скопируйте .env.example в .env.
2. Выполните npm ci.
3. Выполните npm run db:migrate.
4. Выполните npm run dev.
5. Откройте http://localhost:5173.

В .env.example включён AUTH_MODE=dev. Браузер получает локальную сессию без Telegram, но API работает с PostgreSQL. Dev-режим требует NODE_ENV=development и не проверяет, откуда пришёл запрос, поэтому API должен быть доступен только с вашего компьютера.

npm run dev запускает Vite на порту 5173 и API на порту 3001. npm run build собирает оба приложения. npm test проверяет защиту dev-входа и подпись Telegram. npm run test:integration дополнительно проверяет денежные операции в работающей локальной PostgreSQL после миграций. npm run db:studio открывает просмотр базы. npm run format форматирует код через Prettier, npm run format:check проверяет форматирование.

## API и фронтенд через Docker Compose

PostgreSQL должен быть запущен отдельно: сервис `postgres` в `docker-compose.yml` сейчас отключён. Укажите в `.env` `DATABASE_URL` с адресом базы, доступным из контейнера. Если PostgreSQL работает на том же компьютере, используйте `host.docker.internal` вместо `localhost`; Compose добавляет этот адрес и на Linux.

После настройки выполните `docker compose up --build -d`. Compose запустит `api` и `web`, а API применит миграции при старте. Откройте веб-приложение по порту `WEB_PORT`. `VITE_API_BASE_URL` передаётся при сборке фронтенда; после его изменения пересоберите образ. Остановить контейнеры можно через `docker compose down`.

Для локального входа через Docker используйте `AUTH_MODE=dev` только на своём компьютере: Compose открывает порт API на всех сетевых интерфейсах. Для серверного запуска задайте `AUTH_MODE=telegram`, `NODE_ENV=production` и Telegram-параметры ниже.

## Telegram

Для запуска вне локального браузера нужны HTTPS-домен и PostgreSQL, доступная серверу. Настройте обратный прокси на порт API, затем в серверном `.env` установите `NODE_ENV=production`, `AUTH_MODE=telegram`, `DATABASE_URL`, `APP_ORIGIN=https://ваш-домен`, `MINI_APP_URL=https://ваш-домен`, `BOT_TOKEN` и `OWNER_TELEGRAM_ID`. Токен выдаёт [BotFather](https://core.telegram.org/bots/features#botfather). Храните `.env` только на сервере.

После настройки выполните `npm ci`, `npm run build`, `npm run db:migrate`, затем `npm start` под менеджером процессов; для Docker используйте `docker compose up --build -d`. Зарегистрируйте HTTPS-адрес Mini App у BotFather. Бот запускается вместе с API в режиме long polling: автоматически удаляет прежний webhook без сброса ожидающих сообщений и получает сообщения через `getUpdates`. `npm run bot:configure` позволяет отдельно удалить webhook; для обычного запуска эта команда не нужна. Запускайте только один экземпляр API с данным токеном бота.

Команда `/start` в личном чате владельца отправит кнопку открытия приложения. HTTPS нужен для Mini App. Сервер проверяет подпись `initData`, свежесть данных и точное совпадение Telegram ID владельца. Другой ID получит отказ даже при открытии ссылки.

## Данные

Расход, доход и возврат отражаются в записях счетов. Перевод создаёт две записи в одной транзакции базы и не считается доходом или расходом. Повтор отправки с тем же Idempotency-Key не создаёт дубликат. Бюджет и отчёты считают чистые расходы с учётом возвратов. Архивирование сохраняет историю.

До использования реальных данных настройте регулярные копии PostgreSQL отдельно от сервера и проверьте восстановление. Docker volume переживает пересоздание контейнера, но не заменяет резервную копию.

Для ручной локальной копии выполните npm run db:backup. Проверка списка архива выполняется автоматически; сам архив сохранится в gitignored директории backups. Процедуру восстановления на отдельной базе нужно проверить перед production.
